# 指间 · Finger Lab

一个支持本机摄像头及“手机拍摄、电脑显示”的手指实时追踪原型。打开 `index.html` 可预览页面与演示动画；真实摄像头需要安全的浏览器环境。

## 功能

- 一只手的 21 个关键点、骨架和食指光标。
- 短时指尖轨迹、拇指与食指捏合反馈、五指弯曲程度估计。
- 前后摄像头切换、轨迹清除、骨架/轨迹/平滑开关。
- 实际处理帧率和单帧推理耗时；演示模式不显示虚构性能数据。
- 权限、HTTPS、网络加载错误提示；切到后台自动关闭摄像头。
- 电脑创建二维码，手机扫码发送视频，电脑显示视频及追踪结果。
- 本机模式本地识别；手机模式通过 WebRTC 直传配对电脑并在电脑识别。不录制、不采集音频、不向配对服务上传视频。

## 运行

在线测试入口：**[打开 Finger Lab](https://lllikocode.github.io/finger-lab/)**。手机请使用 Safari 或 Chrome 打开，点击“开启摄像头”并允许权限；首次识别需要联网加载模型，也可以先点击“先看演示”。

网站由 GitHub Pages 从公开仓库的 `main` 分支根目录发布，强制使用 HTTPS。

### 手机摄像头 → 电脑

1. 电脑与手机连接同一 Wi-Fi，电脑用 Chrome 打开上面的 HTTPS 网站。
2. 点击“电脑：创建手机连接”，等待二维码出现。
3. 手机扫码，在 Safari 或 Chrome 中打开，选择前置或后置镜头。
4. 点击“开启摄像头并发送”，允许摄像头权限；电脑等待识别模型加载后显示视频和追踪结果。
5. 两端保持页面前台，手机保持屏幕亮着；任一端点击“停止连接”或切后台都会结束会话。再次使用时在电脑重新创建连接并扫码。

手机无需加载识别模型。配对依赖 PeerJS 公共信令服务，电脑识别仍需下载 MediaPipe 模型。视频直接通过局域网 WebRTC 传输，未配置 STUN/TURN；访客网络、客户端隔离、VPN 或浏览器策略可能阻止直连。配对链接仅供自己的手机使用；一个会话只接收一部手机，等待 10 分钟未连接会失效。

### 本机开发

无需 npm 或构建。电脑在项目目录运行：

```sh
python3 -m http.server 4179 --bind 127.0.0.1
```

在同一台电脑的浏览器打开 `http://localhost:4179`。

**自行部署时一起上传 `index.html`、`remote-camera.js` 和 `vendor/` 到 HTTPS 静态托管。** 手机不能用电脑的 `localhost`；普通局域网 HTTP 地址不满足摄像头的安全上下文要求，因此本地 HTTP 页面不提供手机二维码。聊天客户端的文件预览或 iframe 可能没有摄像头授权，需要在系统浏览器单独打开。

## 依赖与限制

界面样式、识别脚本和矢量绘制在 HTML 内，手机连接使用 `remote-camera.js` 及本地保存的 PeerJS `1.5.5`、qrcode-generator `2.0.4`。二维码在浏览器内生成。真正的手部识别需要联网加载固定版本的 MediaPipe Tasks Vision `0.10.21`（jsDelivr，组件加载失败时尝试 unpkg），以及 Google 官方 float16 手部模型版本 `1`。这是**静态网站，不是离线识别包**。部署环境应允许这些模型/组件请求、WebAssembly、blob module worker，以及 PeerJS 公共服务的 HTTPS/WebSocket 请求。公共信令服务不保证可用性，服务故障时页面提示重新连接。

优先使用 Worker 处理识别，界面线程绘制；浏览器不支持时退回主线程 GPU/CPU。最多每秒提交 30 个新视频帧，忙时不排队。FPS 为完成处理的帧率；“单帧处理”仅为检测调用耗时，不是摄像头到屏幕的端到端延迟。

捏合使用指尖距离与掌宽的比值，并以不同的进入/退出阈值减少闪烁。弯曲程度由关节夹角估算，受遮挡、角度及模型误差影响，不用于精密测量。只追踪一只手；多只手同时出现可能导致追踪目标切换。

手机兼容性、发热、实际延迟及网络可达性仍需目标真机测试。前后切换最终取决于浏览器返回的摄像头；只有一只摄像头的设备可能仍使用同一镜头。

技术来源：[MediaPipe Web 文档](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js)、[PeerJS 文档](https://peerjs.com/client/api/peer)。

## 开发验证

日常静态部署无需 npm。更新依赖或运行自动化测试时使用 Node.js 和 npm：

```sh
npm ci
npm run vendor
npm test
```

Windows PowerShell 限制脚本执行时用 `npm.cmd`。测试默认使用 Windows 已安装的 Chrome；其他位置通过 `CHROME_PATH` 指向 Chrome/Chromium 可执行文件。测试使用本地信令服务器、合成视频和模型替身，不访问真实摄像头，不代表真机识别精度或性能。

`npm run test:public` 是可选联网检查，使用真实公共配对服务及 MediaPipe 模型，摄像头仍为合成视频；可读取 `HTTPS_PROXY` 供测试浏览器联网。截图输出到忽略的 `test-results/`。仅自动化本地信令测试为访问回环服务关闭 Chromium 的本地网络检查；产品页面和公网检查不修改浏览器安全策略。
